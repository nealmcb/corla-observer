How it works

  • The QR code holds the page's full hash. It is looked up in the page index of every extract this server has built, and in the evidence commitments recorded for them (SHA256SUMS files stamped with OpenTimestamps and signed with Sigstore).
  • The printed text is read twice, differently prepared, and any line still unclear is read again on its own. Each line is compared with the line as committed: it counts as matched only if what is read is what was committed, and as differing only if two readings agree on something else. A line that cannot be read is reported as unread, never as matched.
  • Two answers are given separately. The content: MATCH (the QR code was read and every line matched), MATCH WITH UNREAD LINES (nothing contradicts the page, but some of it could not be read), MISMATCH (some printed line contradicts the page), or UNKNOWN PAGE (the page could not be found at all). The commitment: whether a published, timestamped evidence commitment covers the page yet, with its proofs; until one does, a match shows only that the page matches this tool's own copy.
  • Anyone can also check a page without this server, from the published evidence: see the provenance sheet's "To check a printed page".
